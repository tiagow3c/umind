## Authenticated routes rules
- The tasks board uses the full available content width; other pages retain the shared reading-width limit so daily columns gain space without widening narrative pages or changing the assistant.
- The authenticated layout owns desktop navigation and a safe-area-aware mobile header/bottom navigation; both share AccountMenu to keep account actions consistent. The desktop menu starts collapsed (icon-only 44px track, labels hidden) and expands to 220px via the header toggle; the choice persists in localStorage ("ata-menu-open") and every NAV item carries an icon. In collapsed mode the track keeps a left-only padding so icons sit on the optical centre of the visible gutter, buttons drop their horizontal padding, and AccountMenu renders its compact (smaller) avatar so nothing overflows the track. Column widths stay in the shell grid so the existing grid-template-columns transition animates menu and assistant changes.
- The new-meeting route creates a draft once per mount and opens the recorder with auto-start; all recording entry points use it to avoid separate preparation flows.
- While recording, a parallel MediaRecorder produces standalone ~30 s windows transcribed immediately into public.live_transcript_chunks; the transcribe stage reuses them only when contiguous and covering the full duration, otherwise it re-transcribes the uploaded parts (diarize/analyze always run on the full audio after stop).
- Mobile pull-to-refresh keeps touch handling in src/components/PullToRefresh.tsx and the distance/threshold math in src/lib/pull-to-refresh-rules.ts with tests; the layout only reads the --pull-offset CSS variable (html[data-pulling]) so the header and content follow the finger, and the gesture is disabled on recorder routes.
